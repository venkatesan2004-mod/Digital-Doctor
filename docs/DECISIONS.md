# Digital Doctor: Architectural Decision Records (ADR)

## ADR-001: Separation of Relational Store (MySQL) and Vector Search Index (ChromaDB)
- **Status**: Approved & Implemented
- **Context**: Medical records require ACID compliance, referential integrity, and audited revisions. Vector databases excel at high-dimensional semantic search but lack robust transactional constraints.
- **Decision**: MySQL 8.0 serves as the authoritative source of truth for all patients, encounters, prescriptions, and orders. ChromaDB is maintained strictly as an auxiliary derived search index for guidelines and encounter chunks.
- **Consequence**: Vector store divergence cannot corrupt clinical records; any vector chunk can be re-indexed from MySQL.

## ADR-002: Dual-Pathway Front-Office Isolation
- **Status**: Approved & Implemented
- **Context**: Hospitals already possess established HIMS workflows for physical physician OPD queues. Forcing all patients into an AI pipeline risks disrupting standard outpatient operations.
- **Decision**: Front-office registration implements two distinct options: `DIRECT_DOCTOR` and `DIGITAL_DOCTOR`. Direct doctor registrations dispatch exclusively to `MockHIMSAdapter` and never generate a Digital Doctor kiosk session.
- **Consequence**: Full backwards compatibility with hospital legacy workflows.

## ADR-003: External CSS Without CSS Frameworks or Utility Classes
- **Status**: Approved & Implemented
- **Context**: The master development specification requires normal external CSS files organized by tokens, layouts, components, and pages, rejecting inline styles or CSS-in-JS.
- **Decision**: A structured 5-layer external CSS system (`tokens.css`, `global.css`, `layout.css`, `components.css`, `pages.css`) was designed using standard CSS variables and semantic BEM-inspired naming.
- **Consequence**: Zero frontend build overhead for CSS toolchains, highly maintainable theme tokens, and clean HTML output.

## ADR-004: Mandatory Human-In-The-Loop (HITL) Order Gating
- **Status**: Approved & Implemented
- **Context**: LLM hallucination in healthcare presents catastrophic patient safety hazards.
- **Decision**: All medication recommendations, lab tests, and imaging requests generated by the AI engine are persisted exclusively in `DRAFT_PENDING_REVIEW` status. Only licensed doctors signing off via the Clinician Review Queue can transition an order to `APPROVED`.
- **Consequence**: AI acts strictly as clinical decision support. Unapproved orders cannot be dispensed or billed.

---

## ADR-005: Kiosk Atomic Privacy Reset
- **Status**: Approved & Implemented
- **Context**: Hospital touchscreens are shared by dozens of patients daily. Any persistent browser state exposes Protected Health Information (PHI) to subsequent visitors.
- **Decision**: Consultation closure purges all tokens from session and local storage, revokes server session access, and resets the kiosk UI to the Welcome screen.
- **Consequence**: Zero data persistence between patient encounters.
